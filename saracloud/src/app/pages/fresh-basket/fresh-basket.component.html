01 — PROJECT OVERVIEW

A smarter way to process orders.

FreshBasket is a cloud-native grocery checkout platform designed to demonstrate how event-driven architecture on AWS can solve a real business problem.

The platform is designed around a simple idea: when a shopper places an order, checkout should remain fast and reliable even when payment, inventory, and notifications complete at different speeds.

Instead of forcing every operation to happen before the customer receives a response, FreshBasket accepts and records the order first, then allows independent AWS services to react to the order event.

02 — THE PROBLEM

When checkout does too much.

Traditional grocery platforms can process checkout synchronously, forcing the browser to wait while several downstream operations are completed.

03 — OUR SOLUTION

Let the order trigger the work.

FreshBasket uses an event-driven architecture where the checkout process accepts and records the order first. The order then becomes an event that other services can consume independently.

06 — ORDER PROCESSING

How an order moves through AWS.

01

Authentication

The shopper authenticates through Amazon Cognito and receives a JWT identity token.

02

Order request

The browser sends a POST request to API Gateway with the customer's authorization token.

03

Validation

API Gateway validates the request, checks authentication, applies throttling, and works with WAF for edge protection.

04

Order intake

The Order Intake Lambda validates business rules and writes the order to DynamoDB with a pending status.

05

Event publication

The Lambda publishes an OrderPlaced event to the custom EventBridge bus.

06

Immediate response

API Gateway returns a successful response with the order ID while downstream processing continues.

07

Independent consumers

Payment, inventory, and notification services react independently to the same order event.

08

Notification processing

Notification messages pass through SQS before the Notification Lambda sends confirmation through SES.

11 — DESIGN DECISIONS

Architecture is also about trade-offs.

01

Event-driven fan-out

Benefit: Resilience, speed, and independent scaling.

Trade-off: Eventual consistency means the interface must communicate that processing is still taking place.

02

SQS for notifications

Benefit: Retry isolation and a clear Dead Letter Queue story.

Trade-off: Payment and inventory use direct event targets, so not every processing path is buffered identically.

03

Cognito + API Gateway

Benefit: A strong identity boundary between shoppers and APIs.

Trade-off: Demo authentication and SES sandbox rules require careful configuration.

04

Amplify Hosting

Benefit: Fast deployment of the Angular storefront with HTTPS and CloudFront delivery.

Trade-off: The website and API use separate origins, making correct CORS configuration important.

05

Simulated payment and inventory

Benefit: Keeps the event-driven architecture easy to demonstrate.

Trade-off: It is not a PCI payment integration or production warehouse management system.

14 — CHALLENGES & LESSONS

What the project taught me.

01

Eventual consistency

Event-driven systems require the interface to communicate that an order is being processed rather than assuming every operation completes immediately.

02

Failure isolation

Not every failure should affect the customer-facing checkout experience. Queues and independent consumers help isolate downstream failures.

03

Cloud security

Authentication, authorization, encryption, IAM, WAF, and secrets management all contribute to a secure cloud architecture.

04

Architecture communication

A strong architecture is not only about implementation. It should also be explainable to both technical and non-technical audiences.

15 — OUTCOME

A working demonstration of event-driven cloud architecture.

FreshBasket demonstrates how a grocery checkout can remain responsive while payment, inventory, and notification workflows operate independently.

The project connects practical customer experience with AWS architecture principles, showing how EventBridge, SQS, Lambda, DynamoDB, Cognito, SES, and other managed services can work together to build a resilient serverless application.
